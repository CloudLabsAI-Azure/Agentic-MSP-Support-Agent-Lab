# Seed data specification

The Service Desk data is generated by `assets/labfiles/seed/generate_seed.py` and loaded by `load_seed.py` into each environment's Dataverse. Generation is deterministic: every environment, and every re-run, gets the same records, numbers and answers; only the dates move, by whole weeks, so that the SLA snapshot falls in the current week. Two runs with the same anchor write byte-identical files. `tests/test_seed_determinism.py` checks the counts, every scenario below and the determinism for anchors across a year (`python -m pytest setup/tests`).

Ticket numbers are assigned by the generator after it sorts the tickets by opening time, and `manifest.json` publishes them: `role_keys` maps every hand-authored ticket's role key to its number, and `scenarios` holds the facts the guides quote. The numbers in this file are the ones the manifest publishes for the default seed; if this file and the manifest ever disagree, the manifest is right. No guide or test hard-codes a number that the manifest does not publish.

## Tables and columns added in version 3

- `spk_customerdocument` (Customer Document): `spk_name`, `spk_documentcode` (alternate key, CDOC-001 to CDOC-036), `spk_CustomerId` (customer), `spk_documenttype`, `spk_body`, `spk_version`, `spk_lastreviewedon`. Lamna Healthcare's two documents are owned by the restricted team.
- `spk_agentaction` (Agent Action): written by the MCP server, no seed rows.
- `spk_ticket`: `spk_subcategory` (global choice, 4 to 6 values per category), `spk_outcome` (closed tickets only), `spk_tags` (2 to 5 lowercase tags from the article, product and version).
- `spk_knowledgearticle`: `spk_relatedarticles`. `spk_technician`: `spk_availabilitynote`. `account`: `spk_servicesinscope`, `spk_configurationnotes`.
- The technician team choice has four values: Service Desk, Infrastructure, Workplace, Security and Identity.

## Values

- The card number in the four sensitive internal notes is 4532 6677 8521 3500, written with and without spaces next to the words "card number" and an expiry date. It is the Luhn-valid example that Microsoft's own documentation uses, chosen so that the Credit Card Number classifier fires (the classifier ignores the payment industry's reserved test numbers). It is not a real card.
- The configuration file and the configuration notes use documentation IP ranges and invented device names; no document holds a secret, a contact email address or a phone number.
- Customer, contact and technician names are fictional (Microsoft sample company names and invented people). The managed service provider is Relecloud Managed Services.
